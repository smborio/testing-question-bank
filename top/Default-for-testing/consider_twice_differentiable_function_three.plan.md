GOAL: Test whether a student can apply Rolle's Theorem twice in sequence to prove that if f is twice differentiable with three distinct zeros a<b<c, then f''(r)=0 for some r. Specifically, test correct identification of which intervals must be closed (continuity/differentiability hypotheses) versus open (location of the guaranteed point), not the ability to invent the overall strategy.

DESCRIPTION: The student sees a single scaffolded proof in three stages, with three randomised zeros a<b<c stated in the prose (the words "open"/"closed" never appear). Six algebraic inputs, each expecting an interval written with oo(·,·)/oc(·,·)/co(·,·)/cc(·,·) notation: blanks 1–2 (Stage 1, hypothesis and conclusion interval for the first application of Rolle's Theorem to f, producing element p), blanks 3–4 (Stage 2, same for a second application producing element q), blanks 5–6 (Stage 3, applying Rolle's Theorem to f' between the student's own p and q, producing r). Nothing in the text assigns which pair of zeros goes with which stage or which bracket type is needed; the student must work that out.

STRUCTURE: Two PRTs. prt_ans1 grades blanks 1–4 jointly: bracket type correct on each of the four blanks (1,3 closed; 2,4 open), plus a pairing check that the two hypothesis/conclusion pairs are exactly {a,b} and {b,c} (in either order, endpoints within a pair unordered), each hypothesis interval's endpoints matching its paired conclusion interval's endpoints. A same-pair branch flags the common error of using {a,b} (or {b,c}) in both applications. prt_ans5 grades blanks 5–6 with follow-through on the student's own blanks 2 and 4 (their p, q): bracket type correct, and endpoint order consistent with whichever of the student's own p,q is numerically smaller (computed from whether their blank-1 pair was {a,b} or {b,c}). A swapped-order branch flags p,q written backwards relative to the student's own earlier work.

RANDOMIZATION: a uniform in {-5,...,-2}, b uniform in {-1,0,1}, c uniform in {2,...,5}, drawn independently; a<b<c holds by construction, no resampling needed.

ANSWER TESTS: Each of the six inputs is an algebraic input restricted to interval notation (oo/oc/co/cc), floats forbidden. prt_ans1 total score is built additively from Maxima-computed components (0.15 per correct bracket type ×4, +0.4 for correct pairing), so bracket-type credit and pairing credit are independent and sum to at most 1.0; the same-pair-used-twice error scores only the bracket-type component it earned (no credit for pairing). prt_ans5 total score is 0.25 each for: blank-5 bracket type, blank-6 bracket type, blank-5 correct follow-through endpoints/order, blank-6 correct follow-through endpoints/order; the swapped-order error loses only the two order-dependent quarters while keeping bracket-type credit.

FEEDBACK: Worked solution (general feedback) presents the canonical proof using {a,b} then {b,c}, noting the reverse order is equally valid. Per-blank feedback explains the closed-vs-open requirement where a bracket type is wrong. Dedicated feedback for using the same pair of zeros twice in Stages 1–2, and dedicated feedback for writing the Stage-3 endpoints in the wrong order relative to the student's own p,q.

IMPLEMENTATION NOTES: Scores are computed as absolute values from feedback-variable expressions (not accumulated by node increments) because additive `+=` scoring across branching nodes produced incorrect totals in rounds 1–2 (full marks awarded on error branches, or non-additive combination of type/pairing credit); round 3 attempted feedback-variable totals but left truescoremode as relative increments in the wrong places, which still broke qtest cases 1/2/4 (full marks where partial was intended); round 4's fix sets truescore equal to the precomputed total (e.g. `score_pairing_ok`, `total_score5`) with truescoremode absolute on every terminal node, which the qtest suite now confirms. Qtest cases 3 and 4 deliberately expect less than 1.0 (0.6/0.5) for the two named error branches, matching the plan's requirement that these never score full marks for the pairing/ordering component.
